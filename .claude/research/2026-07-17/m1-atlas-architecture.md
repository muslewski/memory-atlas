# memory-atlas code architecture audit (M1)

**Date:** 2026-07-17  
**Role:** repo analyst (read-only)  
**Scope:** `bin/`, `lib/`, `adapters/`, `schema/`, `templates/`, `atlas.config.json`, optional-module pattern, build pipeline, init flow, test coverage, public API / extensibility  
**Out of scope:** `visuals/` (syndcast-mind presentation layer)  
**Evidence baseline:** package `0.1.0`, Node ≥20, zero runtime deps, **131 tests passing** (`node --test`, 2026-07-17)

---

## Summary

- **Shape:** zero-dependency ESM CLI (`bin/atlas.mjs` → flat `lib/*.mjs`), JSON config at repo root, Obsidian-compatible vault discovered by structure — not by name.
- **Core loop is sound:** pure verifier (`lib/validate.mjs`) + git resolvers (`lib/resolvers.mjs`) + vault loader (`lib/notes.mjs`) + config merge (`lib/config.mjs`) is the right separation for multi-repo adoption and embedding.
- **Public surface today is CLI-first:** six subcommands (`init`, `build`, `check`, `stamp`, `status`, `routine`); no `package.json` `"exports"` map — consumers import deep paths into `lib/` or copy adapters.
- **Optional modules are half-wired:** `init` can scaffold all seven; only `flows` / `programs` / `vision` affect load/verify. `reference`, `archive`, `backlog`, `drafts` are filesystem/config flags only.
- **Real bug for multi-repo graph quality:** `buildCore` / `runStatus` never pass `vault.decisions` into `validate()`, so decision dangling-link + unmounted-decision attic rows never appear in production `atlas build` (only unit-tested when callers pass `decisions` explicitly).
- **Update story is absent:** additive `init`, tolerant config merge, and copy-paste ONRAMP/skills exist — there is no `atlas update`, versioned migration, or skill that propagates convention upgrades while preserving local vault/config customizations.
- **Test suite is strong on the verifier + config + happy-path CLI, thin on seams that 10+ adopters will stress:** no dedicated `notes`/`resolvers` unit files; no ONRAMP/skills path-sync test (already filed tech-debt); adapter is copy-paste, not a library.
- **Multi-repo pain points already visible:** duplicated vault discovery (CLI / ctx-search adapter / sage example adapter); `vaultDir` informational but unused by CLI; first-structure-match vault pick; triple-maintained defaults (`lib/config.mjs` / schema / init template); `map/index.md` path fixed while `folders.zones` is remappable.
- **Siblings set the interop pattern:** copy-source adapters for agentic-sage and token-oracle (loose coupling, fail-open hooks) — good for independence, expensive when conventions evolve across fleets.
- **Maturity for 5 new minds now is plausible if update + decisions-wire + module semantics land soon; open-source readiness is higher on SPEC/docs than on fleet-update mechanics.**

## Findings

### 1. Layered architecture (what exists)

```
adopting repo
├── atlas.config.json          # repo root; kill switch + folders/modules/anchors/hooks
├── <vault>/                   # discovered by structure (map/index.md | map/zones/)
│   ├── map/index.md           # GENERATED by atlas build (fixed path)
│   ├── map/zones|decisions|flows
│   ├── specs|plans|ideas|tech-debt|templates|…
│   └── …
└── (optional) scripts/nav-refresh-index.mjs  # copy of adapters/ctx-search

memory-atlas package
├── bin/atlas.mjs              # dispatch + build/check orchestration (~243 LOC)
├── lib/                       # flat modules, ~1.8k LOC total
│   ├── config.mjs             # DEFAULTS + tolerant deep merge
│   ├── detect.mjs             # findRepoRoot / findVaultDir
│   ├── frontmatter.mjs        # YAML-subset parser + setFrontmatterField
│   ├── notes.mjs              # loadVault / readNotes(Deep)
│   ├── validate.mjs           # pure core: anchors, verifiedAt, graph, renderIndex
│   ├── resolvers.mjs          # git-backed Resolvers factory
│   ├── ledger.mjs             # specs/plans lifecycle lint
│   ├── init.mjs | stamp.mjs | status.mjs | routine.mjs
├── schema/atlas.config.schema.json
├── templates/{config,notes,routines,vault}

├── adapters/{ctx-search,obsidian-skills}
└── examples/{with-agentic-sage,with-token-oracle,solo}
```

**Zone map (dogfood vault `atlas/map/index.md`):** `config`, `vault-io`, `verifier-core`, `cli`, `agent-onramp` — matches the code split above; `cli` and `agent-onramp` currently report **stale** freshness.

**Normative docs:** `SPEC.md` (convention), `docs/CONFIG.md` (field shape), `docs/ONRAMP.md` (agent wiring), `docs/ADOPTION.md` (brownfield). Decisions: zero-deps (`atlas/map/decisions/0001-…`), YAML-subset (`0002-…`), vault name `atlas` for dogfood (`0003-…`).

### 2. Public API surface

#### 2.1 CLI (primary product surface)

| Command | Implementation | Side effects | Exit semantics |
|---------|----------------|--------------|----------------|
| `atlas init [--vault] [--modules a,b] [--dry-run]` | `lib/init.mjs` | creates dirs/files; never overwrites existing | 0 / 1 usage / 2 fs |
| `atlas build` | `bin/atlas.mjs` `buildCore` + `runBuild` | **writes** `map/index.md` | 1 if hard errors |
| `atlas check [--strict] [--report] [--ledger-only]` | `bin/atlas.mjs` | rewrite index then `git diff` against committed; ledger lint | 1 on errors / dirty index / ledger / strict-stale |
| `atlas stamp <slug...>` | `lib/stamp.mjs` | rewrites `verifiedAt` / maybe `status` / `updated` | 1 if blank/`--all`/missing/unmounted |
| `atlas status [--hook]` | `lib/status.mjs` | none | always 0 (fail-open) |
| `atlas routine [name]` | `lib/routine.mjs` | none (prints prompt) | 0/1 |

**Kill switch:** `atlas.config.json` → `enabled: false` silences every command **except** `init` (exit 0, no output). Implemented in `bin/atlas.mjs` `isKillSwitched`.

**Package bins:** `atlas` and `memory-atlas` → `bin/atlas.mjs` (`package.json`).

#### 2.2 Library exports (de facto; no `exports` field)

`package.json` has **no** `"exports"` map. Anything under published `files` is importable by deep path. Stable-looking exports:

| Module | Notable exports | Intended seam |
|--------|-----------------|---------------|
| `lib/validate.mjs` | `validate`, `renderIndex`, `extractLinks`, `noteIdAliases`, `isExcludePathspec` | **Pure embedding seam** (header documents this) |
| `lib/resolvers.mjs` | `makeResolvers(repoRoot, anchorsConfig)` | Git I/O for anchors |
| `lib/config.mjs` | `loadConfig`, `DEFAULTS`, `DEFAULT_*` | Single source of default shape |
| `lib/detect.mjs` | `findRepoRoot`, `findVaultDir` | Structural discovery contract |
| `lib/notes.mjs` | `loadVault`, `readNotes`, `readNotesDeep` | Vault → note objects |
| `lib/frontmatter.mjs` | `parseFrontmatter`, `setFrontmatterField`, `splitComment` | YAML-subset; stamp-safe rewrite |
| `lib/ledger.mjs` | `lintLedger`, `LIFECYCLES` | Spec/plan lifecycle enums (duplicated in SPEC.md §4) |
| `lib/init|stamp|status|routine.mjs` | `runInit`, `runStamp`, `runStatus`/`computeStatusSummary`, `runRoutine` | CLI handlers, injectible `cwd`/`stdout`/`stderr` |
| `examples/with-agentic-sage/adapter.mjs` | `ownsZone`, `backlogPath`, `claimedWork`, `backlogRows`, `generatedGlobs` | Copy-source sage contract |
| `examples/with-token-oracle/budget-hint.mjs` | CLI script (tested) | Copy-source oracle hook |

**Not exported as library:** `buildCore` / `runBuild` / `runCheck` live only in `bin/atlas.mjs` — embedding tools that want “full check” must reimplement orchestration or spawn the CLI.

#### 2.3 Config / schema surface

- **Runtime defaults:** `lib/config.mjs` `DEFAULTS` (authoritative for CLI).
- **Editor schema:** `schema/atlas.config.schema.json` (`additionalProperties: false` on nested objects; loader still only *warns* on unknown keys).
- **Init template:** `templates/config/atlas.config.json` with `{{VAULT}}` substitution.
- **Dogfood override:** this repo’s `atlas.config.json` sets `vaultDir: "atlas"`, `modules.drafts: true` (default template still has `drafts: false`).

Top-level keys: `version`, `enabled`, `vaultDir`, `folders`, `modules`, `anchors`, `check`, `retrieval`, `skills`, `hooks`, `routines`.

#### 2.4 Templates / skills / adapters (distribution surface)

- **Note scaffolds:** `templates/notes/{zone,flow,decision,spec,plan,program,idea,debt,pillar}.md` — copied into vault on init with `{{DATE}}` substituted.
- **Routines:** `templates/routines/{gardening,session-planning}.md` — vault can shadow under `<folders.templates>/routines/`.
- **Skills (manual copy):** `skills/atlas-nav`, `atlas-recollection`, `writing-for-retrieval` — not installed by `atlas init`; ONRAMP documents hand-copy into `.claude/skills`.
- **Adapters:** `adapters/ctx-search/nav-refresh-index.mjs` is standalone (re-reads config, reimplements vault detection); designed to live at `<repo>/scripts/` after copy. `obsidian-skills/` is README-only guidance.

### 3. Folders / modules optional-module pattern

#### 3.1 Folders (remapping seam — mostly real)

Every loader path that claims to respect remapping goes through `config.folders` (`notes`, `ledger`, `init` core dirs, `stamp` zone path, `routine` vault routines). Documented in `docs/CONFIG.md`.

**Fixed paths (not remappable):**

- Generated index: always `vaultDir/map/index.md` (`bin/atlas.mjs` `buildCore`, `lib/init.mjs`).
- Structural vault detection markers: `map/index.md` or `map/zones/` (`lib/detect.mjs`) — remapping `folders.zones` away from `map/zones` still works if `map/index.md` exists (init creates it).
- BACKLOG: always `vaultDir/BACKLOG.md` (not in `folders` map).

#### 3.2 Modules (scaffold vs runtime asymmetry)

| Module | `init --modules` | Written to `config.modules` | Loaded by `loadVault` | Verifier effect |
|--------|------------------|-----------------------------|-----------------------|-----------------|
| `flows` | dir | yes | if enabled | zones+flows validate; unmounted flows → attic |
| `programs` | dir | yes | if enabled | noteIds + status counts only |
| `vision` | dir | yes | if enabled | pillars for advances↔realizedBy graph |
| `reference` | dir | yes | **no** | none |
| `archive` | dir | yes | **no** | none (retirement is a human move) |
| `backlog` | `BACKLOG.md` | yes | **no** | none (sage example parses it) |
| `drafts` | dir + README | yes | **no** (excluded from search) | none |

**Implication for 10+ repos:** enabling `modules.reference: true` is a directory convention only — graph resolution, status, and check ignore its notes. That is fine if intentional; it is a smell if adopters expect “enabled module = first-class vault citizen.”

### 4. Atlas build pipeline (end-to-end)

```
cwd
 → findRepoRoot (.git walk)
 → findVaultDir (structure, then -atlas/-mind/-brain suffix)
 → loadConfig(repoRoot)  # tolerant merge; never throws
 → loadVault(vaultDir, config)
 → makeResolvers(repoRoot, config.anchors)
 → validate(zones, flows, resolvers, { noteIds, pillars })   # ⚠ decisions omitted
 → renderIndex(result) → write map/index.md
```

**`atlas check` adds:**

1. Same rebuild as build (so working tree index is always regenerated).
2. `git diff --exit-code -- <vault>/map/index.md` — fails if commit is stale relative to regenerate.
3. `lintLedger` on specs/plans (lifecycle enums, summary, zones[] membership).
4. Optional strict freshness: CLI `--strict` **or** `check.strictFreshness`.
5. `--ledger-only` skips verify/index, runs ledger only.
6. `--report` prints ledger coverage line.

**Freshness model (load-bearing product property):**

- `seeded` + `verifiedAt: unverified` → freshness `seeded`.
- `active` + SHA → `git diff SHA..HEAD -- owns.globs` → `ok` / `⚠ stale` / unknown-sha treated stale with warning.
- `unmounted` → attic, **no** anchor evaluation (SPEC + tests strong here).

**Hard vs soft:**

- HARD: empty globs match, missing testid/tool when class enabled, verifiedAt encoding.
- SOFT: routes, empty `enforcedBy`, unconfigured optional anchors, graph dangling/reciprocity, default staleness.

### 5. Init flow

1. Parse `--vault`, `--modules`, `--dry-run`.
2. Resolve repo root (or cwd with warning if no `.git`).
3. Load existing config folders (additive remapping) or defaults.
4. Detect existing vault → additive mode; else create `<basename>-atlas` or `--vault`.
5. Core dirs via `folders.*`; copy vault README; placeholder index; copy note templates.
6. Module actions for requested modules.
7. Write `atlas.config.json` only if missing (`ensureFile` — **never updates** an existing config’s module flags on re-run… wait: modules flags only applied when writing new config; re-run with new `--modules` creates dirs but may leave `modules.*` false in existing config).

**Init / config drift edge case:** second `atlas init --modules flows` on a vault that already has `atlas.config.json` will create `map/flows/` but **will not** flip `modules.flows` to `true` in config (`ensureFile` skips existing config). Result: empty flows dir that `loadVault` still ignores. This will confuse multi-repo operators.

Idempotency for *files* is good (`exists, skipping`); idempotency for *config semantics* is incomplete.

### 6. Extensibility points (designed seams)

| Seam | How | Strength |
|------|-----|----------|
| Pure `validate` + injected `Resolvers` | Fake resolvers in unit tests; other tools can embed | **Excellent** |
| Optional anchor classes | `anchors.testids|tools|routes.enabled` | Good; no plugin API for *new* classes without code change |
| Folder remapping | `folders.*` | Good for layout; fixed index/detection paths remain |
| Module toggles | `modules.*` + init actions | Incomplete (see §3) |
| Config tolerance | unknown keys dropped with warning | Safe for forward-compat of *old* CLI on *new* config keys only if new keys are optional no-ops |
| Routines | vault shadow of built-ins | Good local customization |
| Skills | portable SKILL.md copy | No version pin / update path |
| SessionStart hooks | `--hook` + config toggles; fail-open | Family contract solid |
| Sibling adapters | copy-source examples | Loose coupling; triple-duplicated discovery |
| `entity` type | SPEC extension point only | Not in LIFECYCLES / templates |

**Missing seams for fleet scale:**

- No config **migrations** (`version: 1` exists but no upgrade runner).
- No declared **overlay** for local forks of note templates / skills / adapter scripts.
- No resolver plugin registration (new `owns.*` class requires shipping code in memory-atlas).
- No programmatic “package API version” separate from CLI package semver and SPEC version.

### 8. Code smells & multi-adoption hazards

#### P0 — correctness / trust

1. **`decisions` not passed into production validate**  
   Evidence: `bin/atlas.mjs` lines 83–86 pass only `noteIds` + `pillars`; `lib/status.mjs` same. `validate` supports `graph.decisions` and unit tests cover attic/graph when provided (`test/validate.test.mjs`). Production builds never list unmounted decisions in Attic nor dangling links on decisions.  
   **Impact:** graph section under-reports; adopters who rely on index as source of truth get false “_none_”.

2. **Init re-run does not enable modules in existing config**  
   Evidence: `lib/init.mjs` sets `configObj.modules[name]=true` only when writing new config via `ensureFile`.  
   **Impact:** silent half-enable of optional modules across repos.

#### P1 — fleet / update maturity

3. **No update mechanism** for propagating convention improvements (templates, skills, ONRAMP blocks, adapter scripts, schema defaults) into adopting repos while preserving:
   - local `atlas.config.json` (folders remaps, anchors, hooks, modules)
   - hand-authored vault notes
   - local routine overrides
   - forked skills  

   Comparable industry pattern: [Copier’s three-way update](https://copier.readthedocs.io/en/stable/updating/) — remember template commit + answers, merge template deltas into customized trees. memory-atlas has **additive init only**, which is the opposite of “pull latest convention.”

4. **Triple / quadruple discovery reimplementation**  
   - `lib/detect.mjs`  
   - `adapters/ctx-search/nav-refresh-index.mjs` (`detectVaultDir`)  
   - `examples/with-agentic-sage/adapter.mjs` (`structuralVaultDir` + **also** trusts `config.vaultDir`)  
   Drift risk as structural rules evolve (e.g. multi-vault monorepos).

5. **Defaults triple-sync** (`lib/config.mjs` header already warns): code defaults ↔ schema ↔ `templates/config/atlas.config.json`. No test enforces equality.

6. **Skills/adapters not versioned with adopters** — ONRAMP is copy-paste; package upgrades don’t touch vendored copies. Filed debt: `atlas/tech-debt/agent-onramp-invariant-untested.md`.

#### P2 — seams that will hurt at 10+

7. **`vaultDir` is informational for CLI but meaningful for sage example** — inconsistent companion-tool story; CLI ignores a field adopters may think is authoritative (`docs/CONFIG.md` documents this, but ops still get confused).

8. **First child-dir structure match wins** (`findVaultDir` sorted names). A stray `docs/map/zones` or nested experiment can steal detection from the real vault.

9. **`map/index.md` fixed vs remappable zones** — intentional SPEC, but easy to break detection if someone deletes `map/` while remapping zones.

10. **`loadVault` module gate incompleteness** — reference/archive notes never enter `noteIds`; wikilinks to them always look dangling if someone links them.

11. **CLI split asymmetry:** build/check in `bin/`; other commands in `lib/`. Harder to unit-test check orchestration without spawning binary (integration does spawn — good but slow/heavier).

12. **Zone card / product messaging drift:** `atlas/map/zones/cli.md` summary says “four subcommand implementations” but CLI has six commands (build/check are inline). Stale zone freshness already flagged by dogfood index.

13. **Git is a hard dependency of truth** — correct for this product, but shallow clones / rewritten history → `unknown-sha` → mass stale. No documented CI recipe for `fetch-depth` yet in ONRAMP (ADOPTION mentions strict mode but not shallow clones).

14. **No `package.json` exports** — open-source consumers who want a stable embed API have no contract boundary; any file path can become accidental API.

15. **LIFECYCLES dual maintenance** — `lib/ledger.mjs` header warns: SPEC.md §4 + code must stay in sync manually.

16. **Dogfood vs default naming** — this repo uses vault `atlas/` + `--vault`; greenfield default is `<repo>-atlas`. Both valid; five new repos will mix conventions unless a house rule is written.

17. **Zero-dep constraint is load-bearing** (`0001-zero-dependency-constraint`) — good for adoption surface; means no JSON Schema validation at runtime, no real YAML, no glob lib. Frontmatter subset is a permanent product boundary — good if enforced, fragile if agents emit full YAML.

## Recommendations for memory-atlas (prioritized)

### P0 — before spinning five new minds (days, not weeks)

1. **Wire `decisions` (and consider `debt`/`ideas` if graph should see them) through `buildCore` and `computeStatusSummary`.** Add an integration test that unmounts a decision and asserts Attic + a dangling decision `related` appears under Graph coherence.  
2. **Fix init re-run module enablement:** when `--modules X` is requested and config exists, merge `modules.X=true` (or print a clear “enable in atlas.config.json” warning and exit non-zero if not enabled). Never create a module dir that loadVault will ignore without saying so.  
3. **House rule doc (short) for the five new repos:** vault name (`<repo>-atlas` vs `atlas/`), required CI (`atlas check` vs strict), whether drafts/backlog modules are on by default, recollection commit policy.

### P1 — multi-repo maturity / open-source readiness (the update story)

4. **Design `atlas update` (or skill `atlas-upgrade`) with three layers of merge policy:**  
   - **Machine-safe overwrite:** package-owned files with no local edits expected (e.g. optionally re-copy note templates only if vault template matches last shipped hash; adapter script if unmarked).  
   - **Three-way / AI-mediated:** skills, ONRAMP CLAUDE.md blocks, routines — compare package version A→B, local customized copy, produce a patch or agent plan. Inspiration: Copier’s remembered answers + 3-way merge, but executed by an agent skill that **never** rewrites zone cards or ledger notes.  
   - **Never touch:** vault content under zones/decisions/specs/plans/ideas/tech-debt; `atlas.config.json` keys that differ from defaults (preserve local); `retrieval.excludeFromSearch` customizations.  
5. **Record install provenance:** e.g. `atlas.config.json` → `"packageVersion": "0.1.0"` and/or `.atlas-install.json` listing skill/adapter hashes and last update. Without this, fleet updates are guesswork.  
6. **Single shared `findVaultDir` algorithm** published as the interop contract; generate or document that copy-source adapters must reimplement *that* algorithm — or ship a tiny vendored snippet. Prefer one implementation + “copy this 40-line file” over three diverging stories.  
7. **Triple-sync test:** assert deep equality of folder/module/anchor defaults across `DEFAULTS`, schema defaults (where expressible), and `templates/config/atlas.config.json`.  
8. **ONRAMP invariant test** (close `agent-onramp-invariant-untested` debt): skill dirs + adapter path named in docs exist.

### P2 — architecture seams for 10–50 adopters

9. **Add `package.json` `"exports"`** for a deliberate public library surface:  
   `./validate`, `./config`, `./detect`, `./notes`, `./resolvers`, `./frontmatter` — leave CLI handlers internal or mark experimental.  
10. **Extract `buildCore`/`runCheck` into `lib/check.mjs`** so embedders and tests share one path with the binary.  
11. **Module semantics RFC:** either (a) `reference`/`archive` enter noteIds when enabled, or (b) document them as “filesystem only, not graph members” in SPEC/CONFIG. Ambiguity hurts.  
12. **Resolver extensibility:** either freeze the three optional classes for 1.0, or add a documented hook for custom resolvers (function injection already exists — expose it from CLI via config is the hard part; maybe `anchors.custom` is out of scope and custom classes stay code forks).  
13. **Unit tests for `notes.mjs` and `resolvers.mjs`** (module gates, exclude dirs, route group stripping, empty tools root).  
14. **Monorepo / multi-vault policy:** if any of the five new “repos” are packages in a monorepo, define whether one vault per package or one per git root — current detect assumes one vault per git root.  
15. **Shallow-clone CI note** in ONRAMP/ADOPTION: `fetch-depth: 0` or accept unknown-sha staleness.  
16. **Stamp `cli` / `agent-onramp` zones** after next intentional edit so dogfood index is not permanently stale (trust demo for adopters reading this repo).

### P3 — later / open-source polish

17. Imperative-phrasing lint (SPEC Security stretch).  
18. Parent-atlas aggregation (SPEC non-goal for v0.1 — keep out).  
19. Consider whether `atlas init` should optionally install skills/adapters (with explicit opt-in) vs remaining pure vault scaffold.  
20. Changelog discipline tying SPEC version, config `version`, and package semver — three version axes is fine only if documented in one place.

## Open questions

1. **Update executor identity:** should fleet upgrades be a pure deterministic CLI (`atlas update`), an agent skill (`atlas-upgrade`), or both (CLI does file inventory + 3-way markers; skill does judgment on conflicts)?  
2. **What is the unit of “convention version”?** Package semver, SPEC.md frontmatter version, config `version`, or a new `conventionRelease` field?  
3. **May adopters fork note templates heavily?** If yes, update must never overwrite vault `templates/` without hash check; if no, templates are package-owned and re-copyable.  
4. **Will any of the five new repos be monorepos or multi-package?** Detect-one-vault-per-git-root may be wrong on day one.  
5. **Should `config.vaultDir` become authoritative when set**, with structural detect only as fallback? Would simplify companions but contradict current SPEC interop language.  
6. **Are `reference` / `archive` meant to join the graph eventually?** Current code says no; SPEC describes them as real modules.  
7. **Custom anchor classes:** will any new repo need `owns.*` beyond testids/tools/routes in the next 6 months? If yes, design plugin seam now.  
8. **CI strictness default for the five:** advisory stale forever, or flip `strictFreshness` after a burn-down window?  
9. **Open-source packaging:** publish as `memory-atlas` on npm only, or also as a Claude marketplace skill pack separate from the CLI?  
10. **Relationship to syndcast-mind:** is syndcast expected to `atlas update` onto this package, or remain a frozen origin fork for visuals?
